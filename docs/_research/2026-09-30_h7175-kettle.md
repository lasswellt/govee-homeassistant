# H7175 gooseneck kettle: capabilities, state, AWS IoT push

One H7175 (`devices.types.kettle`) on an account that displays Fahrenheit,
idle, with custom slot 4 selected in the Govee app. Ground truth from the app
at capture time: water 90-100 °F, target 176 °F; built-in presets Green Tea
180, Oolong 195, Coffee 205, Boil 212 °F; custom slots 175, 110, 165 and
176 °F.

The samples are in `tests/kettle_samples.py`; the decoder is
`custom_components/govee/kettle/frames.py`.

## Why the integration needed changes

- The setpoint lives under `temperature_setting/sliderTemperature`. The state
  parser read only the unit hint from that instance (issue #171), so the
  target was never populated.
- The AWS IoT push carries the temperatures under `sta` (`setTem`, `curTem`)
  and in BLE-format frames. The MQTT parser read flat keys only, so the push
  moved nothing but `onOff`. It still counted as a fresh local reading, so the
  coordinator skipped cloud polls and the temperature sensor went stale.

## Capabilities (`/user/devices`)

The full block is `H7175_CAPABILITIES` in `tests/kettle_samples.py`:

| Capability | Parameters |
|---|---|
| `on_off/powerSwitch` | ENUM on=1, off=0 |
| `temperature_setting/sliderTemperature` | STRUCT: `temperature` INTEGER range 40-100 (°C); `unit` ENUM Celsius / Fahrenheit |
| `property/sensorTemperature` | no `parameters` key |
| `work_mode/workMode` | STRUCT: `workMode` ENUM Custom=1, Green Tea=2, Oolong Tea=3, Coffee=4, Black Tea/Boil=5; `modeValue`: for "Custom" a nested ENUM of values 1-4, for the others `defaultValue: 0` |

The H717A (docs/device-catalog.md) differs: workMode M1..M4 = 2..5 with a null
modeValue.

## Decoding

Frames are 20 bytes; the last is the XOR of the preceding 19 (verified on every
captured frame; a frame that fails it is skipped). Byte 0 is `aa` for a status
frame and `3a` for a command or its echo.

| Data | Meaning | Status |
|---|---|---|
| `sta.setTem` / `sta.curTem` | target / current temperature ×100 in the display unit: 176.00 / 90.00 °F | Verified against the app |
| `aa 10 01 <hi> <lo>` | current temperature ×100, always °F (0x2328 = 90.00 °F) | Verified on °F; °F on a °C account per homebridge-govee (unverified) |

Units. The push carries no unit. Temperatures are taken to be in the unit the
kettle declares in `sliderTemperature`; that declaration wins over the
integration's API-unit option, which exists for thermometers that report no
unit. Until a poll has supplied the unit, pushed temperatures are withheld
and the kettle is never skipped as locally fresh. `aa 10` is used only when
the kettle reports °F and `sta` has no current temperature.

Only the H7175 is decoded (`KETTLE_FRAME_SKUS`); the H717A and H7170 share the
capability family but not necessarily the frames, and keep their previous
handling.
