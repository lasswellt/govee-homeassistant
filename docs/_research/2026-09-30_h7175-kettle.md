# H7175 gooseneck kettle: capabilities, state, AWS IoT push

One H7175 (`devices.types.kettle`) on an account that displays Fahrenheit,
idle, with custom slot 4 selected in the Govee app. Ground truth from the app
at capture time: water 90-100 °F, target 176 °F; built-in presets Green Tea
180, Oolong 195, Coffee 205, Boil 212 °F; custom slots 175, 110, 165 and
176 °F.

The samples are in `tests/kettle_samples.py`; the decoder is
`custom_components/govee/kettle/frames.py`.

## Why the integration needed changes

- The setpoint lives under `temperature_setting/sliderTemperature`. The state
  parser read only the unit hint from that instance (issue #171), so the
  target was never populated.
- The AWS IoT push carries the temperatures under `sta` (`setTem`, `curTem`)
  and in BLE-format frames. The MQTT parser read flat keys only, so the push
  moved nothing but `onOff`. It still counted as a fresh local reading, so the
  coordinator skipped cloud polls and the temperature sensor went stale.

## Decoding

Frames are 20 bytes; the last is the XOR of the preceding 19 (verified on every
captured frame; a frame that fails it is skipped). Byte 0 is `aa` for a status
frame and `3a` for a command or its echo.

| Data | Meaning | Status |
|---|---|---|
| `sta.setTem` / `sta.curTem` | target / current temperature ×100 in the display unit: 176.00 / 90.00 °F | Verified against the app |
| `aa 10 01 <hi> <lo>` | current temperature ×100, always °F (0x2328 = 90.00 °F) | Verified on °F; °F on a °C account per homebridge-govee (unverified) |
| `aa 05 00 01 <slot>` | selected mode Custom: `01 04` = custom slot 4 | Verified |
| `aa 05 00 <workMode>` (2..5) | selected built-in mode; byte 4 is not a slot | Verified |
| `aa 05 00 06 <hi> <lo>` | "manual": a target set directly, no preset; bytes 4-5 the target ×100 (`aa05000644c0...2d` = 176.00 °F) | **Inferred** from one live observation |
| `aa 05 <wm> <hi> <lo>` (`wm` 2..5) | built-in preset temperature, ×100: 180, 195, 205, 212 °F | Verified |
| `aa 05 01 <page> [<hi> <lo> <slot> 00] ×2` | two custom-slot temperatures per page, 15-bit ×100; the top bit of `hi` is set on every slot except the app's "DIY" slot | Verified (temperatures, and the flag against the app's DIY badge) |
| `aa 19 <code>` | heating status: 00 idle, 01 heating, 02 keeping warm, 04 reached target (homebridge-govee); 06 seen while a start was scheduled in the app, taken as "scheduled" (tentative) | Verified idle |
| `aa 22 <on> <min u16> <left>` / `3a 22 <on> <min u16> <min lo>` | keep warm: on/off, set duration in minutes (u16), and in the `aa` status the minutes left (equal to the duration until keep warm runs, then counting down); the `3a` command echo repeats the duration | Verified from five app changes and a countdown capture |
| `aa 1f`, `aa 17`, `aa 23` | unknown / scheduled start; not used | Ignored |

Units. The push carries no unit. Temperatures are taken to be in the unit the
kettle declares in `sliderTemperature`; that declaration wins over the
integration's API-unit option, which exists for thermometers that report no
unit. Until a poll has supplied the unit, pushed temperatures are withheld
and the kettle is never skipped as locally fresh. `aa 10` is used only when
the kettle reports °F and `sta` has no current temperature.

Only the H7175 is decoded (`KETTLE_FRAME_SKUS`); the H717A and H7170 share the
capability family but not necessarily the frames, and keep their previous
handling.

### Selected mode and workMode 6

Byte 4 of the selected-mode frame is a slot only for workMode 1 (Custom). After
the target was set directly (`sliderTemperature` 175/176 °F), the kettle pushed
`aa05000644c0000000000000000000000000002d` and the poll reported
`{"workMode": 6}`. workMode 6 is not among the capability's options (1-5) and
bytes 4-5 carry the target just set, so it is read as "manual": a target with
no preset. Before this, byte 4 (0x44) was read as slot 68 and the mode showed
unknown. Any other unlisted workMode shows as unknown and is logged once.

### DIY slot

In the custom-slot pages the top bit of each slot temperature is set on every
slot except one, the slot the Govee app marks "DIY" (its current custom slot).
The badge moves with the chosen custom slot: with slot 4 selected the pages are
`aa050100c45c0100aaf802...67` / `aa050101c074030044c004...98` (slot 4 clear);
with slot 1 selected page 0 was `aa050100445c0100aaf802...e7` (slot 1 clear).
In workMode 6 the app shows no preset selected but keeps the DIY badge, and the
pages keep that slot clear. A push may carry one page only, so a known DIY slot
changes only when a slot in the push is clear or the known one is now flagged.

### Keep warm

| Frame | Meaning |
|---|---|
| `aa22000078780000000000000000000000000088` | status: off, 2 h |
| `aa22010078780000000000000000000000000089` | status: on, 2 h |
| `3a2201001e1e0000000000000000000000000019` | command echo: on, 30 min |
| `3a2201003c3c0000000000000000000000000019` | command echo: on, 1 h |
| `3a2201005a5a0000000000000000000000000019` | command echo: on, 1.5 h |
| `3a22010078780000000000000000000000000019` | command echo: on, 2 h |

The app offers 30, 60, 90 and 120 minutes. The echo arrives the moment a setting
changes; the periodic `aa 22` status can lag. Within one push the status wins.

While keeping warm, byte 5 of the status is the time left:
`aa22010078740000000000000000000000000085` (120 set, 116 left) arrived with
`aa 19 04` (reached target), and the next push, with `aa 19 02` (keeping warm),
showed `aa22010078780000000000000000000000000089` (120 left). A status whose
byte 5 exceeds the duration is skipped.

## How the integration exposes it (H7175)

- `water_heater.<kettle>`: target and water temperature in the kettle's unit;
  operation modes `off`, `custom_1`..`custom_4`, `green_tea`, `oolong_tea`,
  `coffee`, `black_tea_boil`, `manual` (translated). A powered-off kettle
  reports `off`; choosing another mode while off switches it on in that mode
  (mode first, then power). Choosing `manual` re-sends the current target;
  setting the target selects `manual`, so a target together with another mode
  is refused.
- `select.<kettle>_brew_mode` ("Brew mode"): the same keys without `off`;
  choosing one only selects it, on or off, as the Govee app does.
- After a command the kettle is re-read at +5 s and +20 s (one cloud read,
  then a status query; the read yields to the rate limit, the daily budget
  and a running poll). A heating kettle is polled every cycle while the
  budget allows; its own heating status decides when known, except that a
  kettle "keeping warm" far below its target counts as heating (put back on
  the base, it resumes keeping warm and reheats while reporting that).
- A field a push or a command set keeps its value over cloud reads (follow-up
  or regular) until the cloud agrees or 45 s pass: the cloud lags the kettle,
  and a confirming push must not let a stale read flicker the value back.
- The selected custom slot is restored after a restart (the poll reports only
  `{"workMode": 1}`), stored as its (workMode, modeValue).
- Sensors: heating status (enum), keep-warm duration and keep-warm remaining
  (diagnostic; remaining only while keep warm is on), DIY slot
  (diagnostic, enum `custom_N`); binary sensor: keep warm.
- The power switch keeps its unique id and is named "Power" on the H7175, since
  the water heater takes the device name. Diagnostics carry `recent_frames`.
