## #295 — Marketplace domain-collision block

**Mechanism.** These two points are verified directly against home-assistant/core `dev`:
- `homeassistant/components/marketplace/repositories/integration.py`, `async_pre_install`, loops over `self.marketplace.repositories.list_installed`. If any other repository has `category == INTEGRATION` and `data.domain == self.data.domain`, it raises `MarketplaceError(translation_key="integration_owned")`.
- `strings.json:185` defines that message as "The {domain} directory belongs to {owner}."

The check matches on domain alone. It doesn't consult hacs/default or the `removed` list.

**Why some users and not others** (inference, medium confidence). The HACS→Marketplace migration carries over each repository's installed flag. Users who once installed LaggAt/hacs-govee and later installed ours over the same `custom_components/govee` folder still have two `installed: true` records for `govee`. Clean installs don't, which fits the one Container user who updated fine.

**Evidence the cause is not us:**
- Between v2026.10.2 and v2026.11.0 only the manifest `version` changed; `hacs.json` is unchanged.
- Both repos have been in hacs/default for a long time: LaggAt since 2021, ours since 2026-01-19. Neither is in `removed`.
- The same error hits unrelated repos on HA 2026.11.x: kevdliu/hacs-anylist#30, AndrewTapp/solaredgeoptimizers#73 and others listed in core#190454.

**User workaround** (from the core#190454 thread; we have not tested it):
1. Settings → Devices & services → Marketplace → disable.
2. Back up `/config/.storage/marketplace.repositories`.
3. In the `LaggAt/hacs-govee` record, delete only the `"installed": true` line. Leave the lasswellt/govee-homeassistant record alone.
4. Save, re-enable Marketplace, and retry the update.

**Never** use "Delete and uninstall" on the LaggAt entry. It deletes the shared `custom_components/govee` folder and the config entry (core#190454). The fallback is to replace the folder by hand from the release zip and restart.

**Maintainer options.**
- No repo-side change helps. Renaming the domain would break every config entry, and asking hacs/default to drop LaggAt wouldn't clear anyone's local flags.
- Reply on #295 with the cause, the workaround and the core#190454 link. Pin the issue. Optionally add a README troubleshooting row.
- The reply cites no version of ours, so the reply-after-release rule doesn't apply, and 17 users are blocked right now. **Posting now is the recommendation; it needs the maintainer's go-ahead.**

#300 details:
- **Single-frame backwards compatibility holds.** One part passes bytes, not a list, so the AWS IoT payload is byte-identical to before.
- **Validation.** `MAX_PTREAL_FRAMES=64` raises a `ServiceValidationError` with key `too_many_ptreal_frames`, present in both `strings.json` and `translations/en.json`. Every frame is validated before anything is sent.
- **LAN path.** It is used only when LAN is healthy, the device is correlated, it isn't a group, and writes aren't suppressed. A failed LAN send falls back to AWS IoT; this is tested.
- **Behaviour change:** single-frame calls now also prefer LAN when it's healthy. Before, they went over AWS IoT only.
- **Nit (optional).** 64 frames × 28 base64 chars can exceed a 1500-byte UDP datagram on LAN. Consider a cap of about 40.
